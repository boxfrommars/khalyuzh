# Дневник Халюжа

Постоянные правила работы с репозиторием для разработчиков и автоматизированных
агентов.
Изменяемые технические подробности должны находиться в документации, а не здесь.

## Роли документов

- `README.md` описывает приложение, локальную разработку и проверку изменений.
- `DEPLOYMENT.md` задаёт отслеживаемые требования приложения к развёртыванию.
- Этот репозиторий не отвечает за production-инфраструктуру, выполнение deploy
  и серверные runbooks; они поддерживаются отдельно для конкретного окружения.
- При изменении поведения или требований обновлять соответствующий документ
  вместе с кодом.

## Границы изменений

- Работать в существующем PHP/Composer-стеке и сохранять простую архитектуру.
- Не добавлять новые архитектурные слои, абстракции и другие усложнения без
  конкретной необходимости, обусловленной задачей.
- Сохранять публичные URL, русские тексты, API-контракты и визуальный стиль,
  если пользователь прямо не попросил изменить их.
- Не зашивать новое имя питомца или instance-specific профиль в шаблоны и
  runtime-код. Именительный и родительный падежи имени, профиль и рацион
  поступают через контракт конфигурации.
- `public/` остаётся единственным допустимым document root.
- Не менять код, поведение или production-инфраструктуру за пределами задачи.

## Данные и безопасность

- Текущий профиль копируется в новую запись рациона; изменение конфигурации не
  должно незаметно переписывать исторические записи.
- Изменение схемы выполнять только версионированной миграцией. Перед миграцией
  постоянной базы обязательна согласованная SQLite backup-копия.
- Для backup использовать штатный механизм SQLite, а не обычное копирование
  открытой базы.
- Не читать, не изменять и не выводить production-базу или backup без отдельного
  явного запроса пользователя.
- Административные маршруты в production защищаются HTTP Basic Authentication
  на уровне веб-сервера; development-обход нельзя переносить в production.
- Не добавлять в Git секреты, production-конфигурацию, credentials, сертификаты,
  SQLite-базы, journal-файлы и резервные копии.
- Внешний config не может задавать путь к SQLite: каждый экземпляр использует
  только собственный `storage/records.sqlite`.

## Проверки и выпуск

- Точные команды локальной и release-проверки брать из `README.md` и
  `DEPLOYMENT.md`.
- При изменении runtime, зависимостей, маршрутов, assets, writable-путей,
  постоянных данных, миграций, lifecycle hooks или rollback обновлять
  `DEPLOYMENT.md`.
- Не использовать изменяющие API-запросы как production smoke-тесты.
- Commit, push и merge выполнять только по прямому запросу пользователя.
- Production-инфраструктура, выполнение deploy и серверные операции находятся
  за пределами ответственности этого репозитория.
- Сохранять чужие незакоммиченные изменения и перед коммитом проверять полный
  diff на соответствие задаче.
