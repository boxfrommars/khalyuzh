# Дневник Халюжа

Небольшой сайт для учёта рациона и веса Халюжа и подготовки печатного отчёта
для ветеринара. Приложение работает на
PHP 8.3 и SQLite, использует Twig, Symfony HttpFoundation и Symfony Clock.
Frontend-сборки и полноценного PHP-фреймворка нет.

## Роли документов

- `README.md` — описание приложения и инструкция для разработчика;
- `DEPLOYMENT.md` — декларативные требования приложения к развёртыванию;
- `AGENTS.md` — постоянные правила работы агентов с репозиторием;
- production-инфраструктура, выполнение deploy и серверные runbooks находятся
  за пределами ответственности этого репозитория и поддерживаются отдельно для
  конкретного окружения.

## Разделы

- `/` — публичный калькулятор рациона и история кормления списком или графиком;
- `/weight/` — публичное последнее взвешивание, среднее за 7 дней и история
  списком или графиком;
- `/report/` — публичный отчёт о кормлении и фактическом весе для печати или
  сохранения в PDF;
- `/admin/` — управление рационом;
- `/admin/weight/` — управление взвешиваниями.

Публичные страницы доступны без авторизации. Все административные страницы и
API в production защищаются HTTP Basic Authentication на уровне веб-сервера.

## Структура

- `public/index.php` — единственный HTTP front controller;
- `public/` — единственный публичный document root;
- `public/assets/` — CSS и ES-модули без frontend-сборки;
- `app/src/` — классы приложения в namespace `Khalyuzh`: composition root,
  HTTP application, controllers, Database и repositories;
- `app/templates/` — Twig-layout и страницы;
- `app/config.php` — путь к БД, часовой пояс, профиль питомца и параметры
  рациона;
- `storage/` — SQLite-база и локальные резервные копии;
- `bin/migrate.php` — версионированные миграции;
- `bin/backup.sh` — согласованные SQLite backup-копии;
- `tests/` — PHPUnit-тесты на in-memory SQLite.

Записи веса не меняют параметры рациона. Профиль из `app/config.php`
по-прежнему копируется в каждую новую запись кормления, поэтому история
сохраняет исходные параметры.

История на страницах рациона и веса по умолчанию открывается списком. График
показывает до 40 последних записей на календарной шкале; список при этом не
ограничивается. Основная линия графика показывает скользящее среднее за 7
календарных дней по имеющимся записям, а бледная линия с интерактивными точками
сохраняет точные дневные значения. Обе линии соединяют соседние имеющиеся точки
независимо от календарных пропусков; пропуски не превращаются в нулевые значения.
Диапазон нормы остаётся в профиле, snapshots записей и API, но временно не
используется интерфейсом.

## Отчёт для ветеринара

Страница `/report/` объединяет кормления и фактические взвешивания за выбранный
период. Доступны последние 30 или 90 дней, вся история и произвольный диапазон;
по умолчанию показываются последние 90 календарных дней включительно.

Отчёт содержит профиль питомца, краткую сводку, графики, использованные корма и
единую хронологическую таблицу с датой, калорийностью и фактическим весом. В неё
включаются все даты, для которых есть кормление или взвешивание; отсутствующее
значение обозначается прочерком.

Краткая сводка состоит из четырёх показателей:

- средний вес в последние 7 календарных дней выбранного периода;
- изменение этого среднего относительно первых 7 календарных дней периода;
- средняя калорийность в последние 7 календарных дней периода;
- средняя калорийность за весь выбранный период.

Первое среднее веса рассчитывается по имеющимся взвешиваниям в первые 7 дней
выбранного периода и не использует более ранние данные. Последние средние веса и
калорийности рассчитываются по полному trailing-окну из 7 календарных дней до
конца периода включительно. Поэтому для короткого периода они могут учитывать
записи за срок до 6 дней перед его началом. Для каждого среднего достаточно одной
записи; при полном отсутствии записей выводится «Нет данных». Изменение веса
считается как разность неокруглённых последнего и первого средних. Средняя
калорийность за весь период доступна при наличии хотя бы одной записи кормления
и использует только записи внутри выбранного периода.

Все средние калории рассчитываются только по дням с записями и по сохранённым в
них snapshot-параметрам кормов: пропущенный день означает отсутствие данных, а
не нулевое кормление. Вес из snapshot профиля рациона не используется как
результат взвешивания. На обоих графиках показываются только фактические точки
выбранного периода, а данные за предшествующие 6 дней используются исключительно
для расчёта семидневного среднего с первой видимой точки. Фактическая и средняя
линии соединяют соседние имеющиеся точки даже через многодневные пропуски.

Кнопка «Распечатать / сохранить PDF» открывает системный диалог печати
браузера. В нём можно выбрать принтер или сохранение в PDF; отдельная
серверная PDF-библиотека приложению не требуется. Постоянные сведения о
питомце задаются в секции `pet` файла `app/config.php`, а возраст вычисляется на
дату формирования отчёта. На экране показываются имя, вид, порода, пол и
репродуктивный статус, диагноз, окрас, дата рождения и возраст. Печатная версия
использует компактную строку с именем, полом, репродуктивным статусом, диагнозом
и возрастом, чтобы сводка и оба графика помещались на первой странице A4.

## Локальный запуск

Требуется запущенный Docker Desktop:

```sh
docker compose up --build
```

Сайт доступен по `http://127.0.0.1:8088/`, раздел веса — по `/weight/`, отчёт —
по `/report/`,
административные страницы — по `/admin/` и `/admin/weight/`.

При старте development-контейнер применяет миграции к локальной базе и запускает
встроенный PHP-сервер через `bin/router.php`. Router отдаёт напрямую только
пять разрешённых asset-файлов, а все HTTP-маршруты передаёт единому front
controller. Admin разрешён без пароля только при `PHP_SAPI=cli-server`; это
исключение нельзя использовать в production.

## Проверки

```sh
docker compose run --rm app composer validate --strict
docker compose run --rm app composer check
docker compose run --rm app sh -c \
  "find app public bin tests -type f -name '*.php' -exec php -l {} \; && \
   php -r 'exit(extension_loaded(\"PDO\") && extension_loaded(\"pdo_sqlite\") ? 0 : 1);' && \
   sh -n bin/backup.sh && sh -n bin/start-dev.sh"
```

`composer check` запускает PHPUnit и PHPStan level 8. Тесты создают только
in-memory SQLite и не обращаются к `storage/records.sqlite`.

## API

Рацион:

- `GET /api.php` — публичная история;
- `GET /admin/api.php` — история для admin;
- `PUT /admin/api.php?date=YYYY-MM-DD` — создание или обновление;
- `DELETE /admin/api.php?date=YYYY-MM-DD` — удаление.

Тело `PUT`:

```json
{
  "dryAmount": 40,
  "wetAmount": 1
}
```

Вес:

- `GET /weight/api.php` — публичная история;
- `GET /admin/weight/api.php` — история для admin;
- `PUT /admin/weight/api.php?date=YYYY-MM-DD` — создание или обновление;
- `DELETE /admin/weight/api.php?date=YYYY-MM-DD` — удаление.

Тело `PUT`:

```json
{
  "weightKg": 5.48
}
```

Для каждой даты хранится не более одной записи веса. Будущие даты и
неположительные значения отклоняются.

## Миграции и backup

Новая или существующая база подготавливается командой:

```sh
php bin/migrate.php
```

Перед миграцией постоянной базы обязательна согласованная backup-копия:

```sh
./bin/backup.sh
```

Backup использует SQLite `.backup`, содержит обе предметные таблицы и хранит
последние 30 файлов. Обычное копирование открытой SQLite-базы не заменяет этот
механизм.

## Production

Production-зависимости устанавливаются воспроизводимо:

```sh
composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader
```

`public/` должен оставаться единственным document root. Nginx должен исполнять
только `public/index.php`, отдавать напрямую только известные assets и защищать
весь `/admin/` через HTTP Basic Authentication. Пример конфигурации находится
в `deploy/nginx.example.conf`. Полный
deployment-контракт, порядок миграции и rollback описаны в `DEPLOYMENT.md`;
production-инфраструктура, выполнение deploy и серверные runbooks находятся за
пределами ответственности этого репозитория.
